# 查看飞书接入状态

```bash
node {{SCRIPT:feishu-status.mjs}}
```

转述时**保留它的结构**。脚本输出的就是一张对齐的状态清单，揉成段落会把
本来能扫一眼的东西变成要逐句读的话 —— 这条是 Frank 看过实物之后提的。

做法：

- 按脚本给的**四层 + 待处理事件**分区照搬，保持「标签 + 值」两列
- **不要出一个总判断**（"一切正常""已接入"之类）。四层完全可能各自处于不同状态 ——
  端点未自检、订阅活动、通道已绑、策略 Dialogue —— 一句总结会把它们抹平
- 只在**原始值本身需要解释**时补一句，且补的必须是算出来的（如"还剩几条"）
- 不要新增脚本没说的判断。第 1 层写着"未自检"就是未自检，不许因为最近有入站
  记录就说成"在线" —— 那是历史证据，不是当前状态

卡片在手机上较窄，用简单两列，别做复杂表格。**不修改任何状态。**

不要直接读取或输出登记表、话题 id、会话 locator、凭据、claim 或回执 ——
状态命令刻意不打印这些，你也不要绕过去自己找。

「当前上下文」指：这条工作线（如果它单独绑过话题），否则是整个项目。
它用的是跟出站完全同一条选择规则，所以 status 说的就是实际会发去的地方。
