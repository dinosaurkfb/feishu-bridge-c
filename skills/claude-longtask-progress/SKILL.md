# 你的回答会被转发到飞书

这个项目接了飞书桥。**你每一轮回答的正文，会在这轮结束时被原样发到 Frank 的飞书话题里。**

不是摘要，不是你挑出来的要点 —— 是你说的那段话本身。取自 Stop 钩子的
`last_assistant_message`，纯脚本转发，不经模型、不做判断。

**前提是这个项目已经接了桥。**没接的项目什么都不会发生 —— 钩子照跑，
但在登记表里查不到这个目录，就静默退出。想知道接没接：

```bash
node /Users/dk/claude-projects/feishu-bridge-cc/scripts/bind-preview.mjs
```

这条**已经在权限白名单里**，不会弹确认 —— 它只打印，代码层面就发不了任何东西
（依赖图里没有发送模块，有测试盯着）。已接入的项目会告诉你话题在哪。

## 把一个新项目接进飞书

**只在 Frank 明确要求时做这件事**（「把这个项目接到飞书」「给它建个话题」之类）。
不要因为「这个项目看起来该接」就自己接 —— 每接一次，群里就永久多一个话题，
而话题是撤不干净的。

```bash
node /Users/dk/claude-projects/feishu-bridge-cc/scripts/bind-preview.mjs           # 先看（免确认）
node /Users/dk/claude-projects/feishu-bridge-cc/scripts/bind-project.mjs --apply   # 再做（弹确认）
```

**先跑预览，把根消息正文给 Frank 看过再 `--apply`。**那条消息发出去就改不了了。
第二条会弹权限确认，**那是应该的** —— 别把它当故障去绕。

预览要是也跑不了，就把命令交给 Frank 让他自己敲 `! node …`，
**不要去读源码把根消息「逐字还原」**给他看：还原出来的东西看着像脚本输出，
其实是你算的，差一个字他就是照着一份假预览点的头。

它做两件事：在群里建一条根话题，往登记表加一行。**项目目录里一个文件都不写** ——
群、身份、profile 这些是机器级的，装的时候配一次；项目叫什么、干什么从 CLAUDE.md 取
（一级标题当名字，第一段第一句当用途；没有 CLAUDE.md 就用目录名，绝不为取名字失败）。

每个项目一辈子一次；重复跑是安全的（平台侧幂等键挡住重建），会直接告诉你已经接过了。

### 同一个项目里有多条工作线

默认是**一个项目一个话题** —— 项目里所有会话的回答都发到同一个地方。

如果这个项目里同时有几条互不相干的线（常见于非纯代码的工作：一条查资料、一条写稿、
一条整理数据），可以让**某一条线单独占一个话题**。在那条线自己的会话里跑：

```bash
node /Users/dk/claude-projects/feishu-bridge-cc/scripts/bind-session.mjs           # 先看
node /Users/dk/claude-projects/feishu-bridge-cc/scripts/bind-session.mjs --apply   # 再做
```

**必须在要绑的那个会话里跑** —— 它从环境变量认自己，再拿会话登记文件交叉核对，
对不上就拒绝（免得在派生进程里绑错线）。

项目级绑定不受影响：没单独绑过的会话照旧发到项目那个话题。**会话级是加法，不是替换。**

接完之后**出站立刻可用**，下一轮回答就会发到新话题。

**入站还差最后一下**：让 Frank 去那个新话题里 @ 一下运输 agent（空消息也行），
绑定才算完成 —— 建话题的那一刻 Aily 的 session 还不存在，它是第一条消息流进来才产生的，
所以绑定必然分两段。**在他真的 @ 过之前，别说入站通了。**

## 为什么是原样转发

因为**判断会出错，而错的方向是不对称的**：

- 多发一条 Frank 已经读过的 → 噪音，代价约等于零
- 漏发一条他没看到的 → 他走开了，结果只躺在一个他看不见的终端里

他可能在你干活的任何一刻离开电脑。用一个会出错的判断去决定发不发，
是拿便宜的错误换昂贵的错误。所以不判断。

## 这对你写字的要求

**假设读者在手机上，没看终端。**他看不到你的工具调用、看不到文件内容、
看不到你读了什么。所以：

- 结论要能独立成立，不能依赖「你刚才看到的那个输出」
- 提到文件和数字就把关键的那部分带上，别只说「如上所示」
- 飞书文本消息**不渲染表格**。复杂表格过去会变成一堆竖线，重要信息别只放表格里

**不要因为「会被转发」就把回答写成汇报体。**他要的是结论和依据，
不是「本次工作总结」。正常说话就行。

## 你不需要手写进展

`scripts/outbox.mjs` 那套五类（milestone / decision / risk / pending / next）
**已经退居二线**，只服务没有对话轮次可依附的东西 —— 比如绑定到期体检，
那是钩子自己生成的。

你在回答里说过的话已经会被转发，再手写一条摘要就是重复。**别记。**

唯一还值得手动记一条的情况：你在一轮回答**之外**发现了什么
（比如后台任务的输出里有个异常），而这轮回答不会提到它。这种时候：

```bash
node /Users/dk/claude-projects/feishu-bridge-cc/scripts/outbox.mjs \
  --kind risk --text "<一句话>" --source longtask
```

## 一条纪律没变

**没做成就别说做成了。**被权限拦下、跑失败、只做了一半 —— 如实说。
转发是原样的，所以你怎么说，Frank 就怎么收到。**伪造进展比不报告进展糟得多。**

## 边界

- 你**不发飞书消息**。发布由出站发布器做，用哪个身份由机器级配置决定。
- 你**不碰 `.runtime-data/`**。那里是映射、claim、回执和 outbox 队列，
  由入站路由器和发布器维护 —— 干活的一方不该能伪造自己的回执。
- 发不出去时进展留在队列里，兜底定时器每 30 分钟重试。
  **绝不会出现「标记已发但实际没发」** —— 发送成功才标记。
