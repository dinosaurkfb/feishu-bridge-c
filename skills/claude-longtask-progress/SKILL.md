# 你的回答会被转发到飞书

这个项目接了飞书桥。**你每一轮回答的正文，会在这轮结束时被原样发到 Frank 的飞书话题里。**

不是摘要，不是你挑出来的要点 —— 是你说的那段话本身。取自 Stop 钩子的
`last_assistant_message`，纯脚本转发，不经模型、不做判断。

## 为什么是原样转发

因为**判断会出错，而错的方向是不对称的**：

- 多发一条 Frank 已经读过的 → 噪音，代价约等于零
- 漏发一条他没看到的 → 他走开了，结果只躺在一个他看不见的终端里

他可能在你干活的任何一刻离开电脑。用一个会出错的判断去决定发不发，
是拿便宜的错误换昂贵的错误。所以不判断。

## 这对你写字的要求

**假设读者在手机上，没看终端。**他看不到你的工具调用、看不到文件内容、
看不到你读了什么。所以：

- 结论要能独立成立，不能依赖「你刚才看到的那个输出」
- 提到文件和数字就把关键的那部分带上，别只说「如上所示」
- 飞书文本消息**不渲染表格**。复杂表格过去会变成一堆竖线，重要信息别只放表格里

**不要因为「会被转发」就把回答写成汇报体。**他要的是结论和依据，
不是「本次工作总结」。正常说话就行。

## 你不需要手写进展

`scripts/outbox.mjs` 那套五类（milestone / decision / risk / pending / next）
**已经退居二线**，只服务没有对话轮次可依附的东西 —— 比如绑定到期体检，
那是钩子自己生成的。

你在回答里说过的话已经会被转发，再手写一条摘要就是重复。**别记。**

唯一还值得手动记一条的情况：你在一轮回答**之外**发现了什么
（比如后台任务的输出里有个异常），而这轮回答不会提到它。这种时候：

```bash
node /Users/dk/claude-projects/feishu-bridge-cc/scripts/outbox.mjs \
  --kind risk --text "<一句话>" --source longtask
```

## 一条纪律没变

**没做成就别说做成了。**被权限拦下、跑失败、只做了一半 —— 如实说。
转发是原样的，所以你怎么说，Frank 就怎么收到。**伪造进展比不报告进展糟得多。**

## 边界

- 你**不发飞书消息**。发布由出站发布器用 COO助理CC 的身份做。
- 你**不碰 `.runtime-data/`**。那里是映射、claim、回执和 outbox 队列，
  由入站路由器和发布器维护 —— 干活的一方不该能伪造自己的回执。
- 发不出去时进展留在队列里，兜底定时器每 30 分钟重试。
  **绝不会出现「标记已发但实际没发」** —— 发送成功才标记。
